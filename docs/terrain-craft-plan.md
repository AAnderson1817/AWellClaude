# Terrain construction plan after the material checkpoint

The current native views show a machined ashlar grid and rounded raw rock. The governing cornice and rock-seam references instead depend on broad worked planes, a few meaningful broken edges, and deep angular cleavage. The next terrain pass should change those forms before increasing texture contrast.

1. **Dressed stone:** replace the general ashlar `box()` fronts in `masonry()` with shallow piecewise-planar faces. Use two or three broad cut planes rather than a dense displaced grid. Vary narrow bedding gaps and arris widths coherently; the current universal `.024` inset and repeated bevel are visible as a black grid. Place sparse recessed corner chips on selected internal faces, not uniform damage on every block. Derive unequal course heights over contiguous facade regions instead of forcing every joint to the original tile row. Preserve the original continuous standing caps, collision-edge bands and sealed portal construction.

2. **Vault rock:** replace the smoothly shaded `relief()` field with clipped angular cleavage patches and narrow recessed fracture returns. Keep broad faces planar with intentional normal breaks at geological boundaries. Simply disabling smoothing on the existing jittered five-by-five cell grid would expose triangulation noise. Clip patches to the unchanged raw-rock mask and retain the current exact `z=0` contact/perimeter band. Fine grit remains in the material; large planes and fracture depth belong to this geometry.

3. **Evidence before propagation:** first inspect one balcony-wall study and one door-side raw-rock study under neutral and grazing light, then the locked game camera. Accept broad construction only if its volume reads without exaggerated texture contrast. Apply the proven construction to the rooms, then reopen source, reimport GLBs, run the independent map/contact/normal checks, and capture both rooms.

Protected data: `src/room.c` masks and player behavior; existing room/collection and asset identities; `FOUNDRY_VAULT_TERRAIN` / `FOUNDRY_DROWNED_TERRAIN`; column and doorway identities; all true landing lines; material family meanings; no front geometry beyond `z=0`. Keep the current maximum twelve material groups per room and sixteen-bit mesh indices. The existing combined terrain allowance is 100,000 triangles, with the current delivery near that limit. Replace redundant bevel/tessellation work rather than spending geometry uniformly; flag a measured budget conflict before changing the allowance.

This plan does not authorize editing the terrain delivery during the current material capture/hash checkpoint. Root releases ownership after that checkpoint is committed. The material library remains a separate editable source and portable texture package.
